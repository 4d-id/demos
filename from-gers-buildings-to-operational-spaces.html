From GERS buildings to operational spaces

Quantum Studio · November 2026 · 6 min read
Overture GERSInteroperability

In this essay

  2. Different questions

Overture's Global Entity Reference System solved a problem that was blocking the whole industry: mapped entities now have stable, open, global identifiers that anyone can join data against. That is a genuinely important piece of infrastructure, and 4D-ID is better off because it exists. This note is about how the two compose, because they answer different questions, and the most useful thing a 4D-ID record can carry is often a GERS ID.

What GERS gives everyone

GERS assigns a stable identifier to entities in Overture's reference map: buildings, places, addresses, road segments, and administrative divisions. The identifiers are open, they are global, they stay stable across releases, and bridge files connect source dataset identifiers to them. The effect is that two organizations holding data about the same building can join on an identifier instead of running a conflation pipeline against each other's geometry. That removes a tax almost everybody in geospatial was paying.

It is worth being specific about why this matters to an identity layer rather than treating it as background. The single hardest thing about any shared naming scheme is convergence: getting two parties who never coordinated to end up on the same name for the same thing. Every mechanism for that is some flavor of rendezvous through an identifier the world already assigns. A stable, open, global identifier for mapped entities is the best rendezvous material that has ever existed at this scale.

Different questions

The two systems are not competing for the same slot, and the clearest way to see it is to look at what each one is asked at runtime.

GERS answers

Which mapped entity is this? Is the building in your dataset the same building as the one in mine? Has this entity's identifier stayed stable since the last release? Which source records contributed to it?

4D-ID answers

Which specific operational thing is this, including things no reference map carries? What is its current state, who said so, and when? What happened to it over time? Which representations depict it? Was it merged with something else, by whose authority?

A GERS ID identifies an entity in a reference map. A 4D-ID identifies an entity that some authority chose to track operationally, which includes things that are in the reference map and a very large number of things that are not and should not be: an individual sprinkler head, a dock door, a forklift, a floor-level anchor inside a scan, a work zone that exists for three weeks, a specific window on the fourth floor that an interior capture and an exterior model both need to agree about.

Those things do not belong in a global reference map. They are too numerous, too short-lived, too specific to one operator's workflow, and often too sensitive. But the systems that work with them still need a persistent name, state over time, provenance, and a way to reconcile duplicates. That is the layer 4D-ID is for.

A GERS ID is a rendezvous identifier, and that is a compliment

In the 4D-ID data model, an external identifier attaches to an entity through an identified_as relation. It says: this entity is the thing that registry calls by that name. Parcel numbers, asset tags, building-model GUIDs, listing identifiers, and GERS IDs all arrive through the same door.

4did:id:5a89fc81f07739510a815e8c202160ac:7KQ2P4M9XRB6TJ0VN3YH8D
  identified_as  overture.gers / fea28f69-7afa-460c-b270-61ef74cd340c
  identified_as  acme.cmms     / BLDG-4471
  registered_in  h3:12         / 8c2a100d2d0dbff   (anchor, 2026-11-02, ±4 m)

Nothing here replaces the GERS ID. It is not rewritten, wrapped, or deprecated. It is carried, and carrying it is what makes convergence work: two organizations that each attach the same GERS ID to their own record of a building have, without coordinating, pointed at the same subject. That is the resolve-before-mint path working on the strongest possible evidence, and it is the reason the bridge exists.

The GERS bridge adapter makes that path inspectable. It verifies membership from a supplied registry capture, evaluates source-binding evidence separately, checks exact aliases first, and routes incomplete or ambiguous cases to review. When policy permits a reference-only mint, the accepted GERS ID becomes an identified_as relation. Run the same import against the same durable store again and the alias resolves to the existing identity instead of creating another. The bundled writer is deliberately local and provisional; it does not claim that a production resolver or Overture accepted the result.

Where the operational layer starts

Take a warehouse that is in Overture with a GERS ID. The reference map knows the footprint, and that is the correct scope for a reference map. The operator needs a different set of facts, none of which a global basemap should be asked to hold:

  • Dock doors 1 through 14, individually, because dispatch addresses them individually.
  • A forklift whose position changes every few seconds and whose identity must survive a battery swap, a depot transfer, and two fleet-management vendors.
  • A temporary work zone in aisle C that exists for eleven days.
  • Three interior scans captured in different months, each registered to the building, each needing to resolve to the same rooms as the others.
  • An asset tag from the maintenance system, a listing identifier from the leasing system, and a BIM GUID, all of which refer to the same building and currently cannot be joined without a per-pair integration.

The building has one 4D-ID carrying its GERS ID, its asset tag, and its BIM GUID. The dock doors and the forklift and the work zone have their own 4D-IDs with the building as parent or as a registration. A system holding only the GERS ID can start at the building and walk down. A system holding only an asset tag arrives at the same building from a different direction. Neither had to agree with the other in advance.

The boundary, stated plainly

What neither layer does

Neither GERS nor 4D-ID performs detection, segmentation, localization, or geometric registration. Deciding that a scan cluster is the same physical window as a mesh face is spatial work done by other systems. An identity layer stores the answer, its evidence, and who stands behind it. It does not compute it.

Composition, concretely

The practical recommendation for anyone building on both is short:

  • Join on GERS where GERS has coverage. If the entity you care about is a building, place, address, or road segment in the reference map, the GERS ID is the right joining key and should be the first thing you attach.
  • Resolve before you mint. Check whether an entity carrying that GERS ID already exists before creating a new 4D-ID. This is the single rule that keeps a permissionless naming scheme from degenerating into duplicates.
  • Mint 4D-IDs for the operational layer. Components, equipment, temporary zones, capture-specific anchors, and anything whose state changes faster than a map release.
  • Keep the anchor as a registration, not as the name. A grid cell routes and filters. It anchors an identity; it is not the identity, and it is not a current position.
  • Let identifiers accumulate. An entity carrying a GERS ID, a parcel number, an asset tag, and a BIM GUID is more valuable than one carrying any single identifier, because each one is a door a different system can arrive through.

GERS made the mapped world joinable. The work left is the operational layer underneath and around it: the things that move, the things that are too granular or too temporary for a reference map, and the continuity of all of it over time. That is a complementary job, and the bridge between them is a few hundred lines of adapter code, which is roughly how it should be when two layers are actually composing rather than competing.

4D-ID is a working draft offered for community review. If the shape of the identified_as relation makes it awkward to carry a GERS ID well, that is a specification bug worth reporting, and it is the kind of feedback the draft stage exists for.

Keep exploring.
